## 1. Architecture Overview

The ZK proof system has three distinct execution environments that must stay synchronized:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           PROOF GENERATION FLOW                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   FRONTEND (Browser)          BACKEND (Sunspot)        SOLANA (On-chain)   │
│   ──────────────────         ─────────────────         ─────────────────   │
│                                                                             │
│   ┌──────────────┐                                                          │
│   │ public/*.json│  NoirJS witness                                          │
│   │ (ACIR)       │──────────────┐                                          │
│   └──────────────┘              │                                          │
│          │                      ▼                                           │
│          │              ┌──────────────┐                                   │
│          │              │   Witness    │                                   │
│          │              │   (~2 sec)   │                                   │
│          │              └──────────────┘                                   │
│          │                      │                                           │
│          │                      │ witness data                              │
│          │                      ▼                                           │
│          │              ┌──────────────┐        ┌──────────────┐           │
│          │              │ Sunspot      │        │ Verifier     │           │
│   From same source ─────│ Groth16      │───────▶│ Program      │           │
│   (circuits/*.nr)       │ (~10 sec)    │ proof  │ (<400k CU)   │           │
│          │              └──────────────┘        └──────────────┘           │
│          │                      ▲                      ▲                    │
│          ▼                      │                      │                    │
│   ┌──────────────┐      ┌──────────────┐      ┌──────────────┐            │
│   │ circuits/    │      │ *.ccs        │      │ *.vk (deploy)│            │
│   │ target/*.json│──────│ *.pk         │──────│ verifier.so  │            │
│   │ (ACIR)       │      │ (Sunspot)    │      │ (Solana)     │            │
│   └──────────────┘      └──────────────┘      └──────────────┘            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Key Insight: Three Versions of the Same Circuit

Every circuit exists in **three forms** that must be compiled from the **same source**:

| Form | Location | Used By | Purpose |
|------|----------|---------|---------|
| ACIR JSON (target) | `circuits/target/*.json` | Sunspot | Input for Groth16 compilation |
| ACIR JSON (public) | `public/*.json` | NoirJS (browser) | Witness generation in browser |
| Constraint System | `circuits/target/*.ccs` | Sunspot prover | Groth16 proof generation |

**If these get out of sync, witness sizes won't match and proofs will fail.**

| Artifact | Location | Generated By | Purpose | 13-card Size |
|----------|----------|--------------|---------|--------------|

| Verifier program | `*_verifier.so` | GitHub workflow | Solana program | ~200KB |

> **Download from workflow:** `.pk`, `.vk`, `*_verifier.so`, `*_verifier-keypair.json`
> **Generated locally:** `.json` (via `nargo compile` + `npm run sync-circuits`)

### 2.2 Current Circuits

| Circuit | Purpose | Key Private Inputs | Public Inputs |
|---------|---------|-------------------|---------------|
| `shuffle_proof` | Prove valid deck permutation | `seed`, `shuffled_deck[13]` | `deck_commitment`, `original_deck[13]` |

```
            ▼  nargo compile (in each directory)

STEP 2: Sync to Browser

            │
            ▼  npm run sync-circuits
            │
public/shuffle_proof.json            ◄── Browser uses these
public/deal_proof.json

STEP 3: Generate Groth16 Artifacts
──────────────────────────────
circuits/target/*.json
            │
            ▼  sunspot compile target/<circuit>.json
            │

            │
            ▼  sunspot setup target/<circuit>.ccs
            │
solana-verifiers/target/*.pk         ◄── Proving key

STEP 4: Deploy Verifier (if changed)
──────────────────────────────
solana-verifiers/target/*.vk
            │
            ▼  sunspot deploy target/<circuit>.vk
            │
Deployed Solana Program              ◄── New program address
```

### 3.2 Dependency Chain

```
main.nr ──► nargo ──► .json ──► sunspot compile ──► .ccs ──► sunspot setup ──► .pk/.vk ──► sunspot deploy
   │                    │
   │                    └──► sync-circuits ──► public/*.json (browser)
   │
   └── ANY CHANGE HERE REQUIRES FULL REBUILD DOWNSTREAM
```

## 4. Common Errors & Diagnostics

### 4.1 Error: "invalid witness size, got X, expected Y"

**Example:**
```
Error: invalid witness size, got 773, expected 16699
```

**Root Cause:** The witness generated by NoirJS (browser) doesn't match what Sunspot expects. This happens when:
1. `public/*.json` was compiled from a different circuit version than `*.ccs`
2. Usually: circuits were recompiled for 13-card deck, but Sunspot artifacts are still 52-card

**Quick Diagnosis:**
```bash
# Check .ccs file sizes - 13-card circuits should be 1-2MB, 52-card would be 20MB+
ls -lh circuits/target/*.ccs

# Check public JSON sizes - should match target/*.json
ls -lh public/*.json circuits/target/*.json

# Grep for deck size in source
grep -n "shuffled_deck:" circuits/*/src/main.nr
```

**Size Reference (13-card vs 52-card):**
| Deck Size | `.ccs` Size | `.pk` Size | Witness Elements |
|-----------|-------------|------------|------------------|
| 13 cards | **175-263 KB** | **280KB-2.3MB** | ~773 |
| 52 cards | ~20 MB | ~200 MB | ~16699 |

**Current 13-card expected sizes:**
| Circuit | `.ccs` | `.pk` |
|---------|--------|-------|
| shuffle_proof | ~263 KB | ~2.3 MB |
| deal_proof | ~175 KB | ~852 KB |
| reveal_proof | ~44 KB | ~280 KB |

**Fix:**
1. Push circuit changes to `main` OR manually trigger GitHub workflow
2. Download `solana-verifiers` artifact after workflow completes
3. Copy `.ccs`, `.pk`, `.vk` files to appropriate directories
4. Run `npm run sync-circuits`

See [Section 5: Rebuilding Artifacts](#5-rebuilding-artifacts-github-workflow) for detailed steps.

---

### 4.2 Error: "Proof verification failed on-chain"

**Root Cause:** The verifier program on Solana doesn't match the proving key used.

**Diagnosis:**
```bash
# Check if verifying key changed since last deploy
ls -la solana-verifiers/target/*.vk
```

**Fix:**
1. Trigger GitHub workflow with **"Deploy to devnet"** checkbox enabled
2. After workflow completes, note the new program IDs from the workflow summary
3. Update program IDs in:
   - `CLAUDE.md` (Deployed Programs table)
   - `hooks/useGameProgram.js` (IDL program addresses)

> ⚠️ `sunspot deploy` cannot run locally - use the GitHub workflow.

---

### 4.3 Error: "Circuit X not found" in browser

**Root Cause:** `public/*.json` is missing or corrupted.

**Diagnosis:**
```bash
# Check public directory
ls -la public/*.json
```

**Fix:**
```bash
npm run sync-circuits
```

---

### 4.4 Error: "Constraint count mismatch"

**Root Cause:** Using incompatible versions of Noir compiler or Poseidon library.

**Critical Pins (do not upgrade without testing):**
- Poseidon: v0.2.2
- Noir: 1.0.0-beta.18

**Diagnosis:**
```bash
# Check Noir version
nargo --version

# Check Poseidon version in Nargo.toml
cat circuits/shuffle_proof/Nargo.toml | grep poseidon
```

## 5. Rebuilding Artifacts (GitHub Workflow)

> ⚠️ **IMPORTANT: Sunspot cannot run locally** due to version mismatches between local Rust/Solana toolchains and Sunspot's requirements. All Sunspot compilation must be done via the GitHub Actions workflow.

### 5.1 Why Local Sunspot Doesn't Work

Sunspot requires specific versions of:
- Rust toolchain
- Solana CLI (Agave)
- Go compiler
- cargo-build-sbf

These versions often conflict with local development environments. The GitHub workflow uses a clean Ubuntu environment with pinned versions that are known to work together.

### 5.2 The GitHub Workflow

**Location:** `.github/workflows/build-sunspot-verifiers.yml`

**What it does:**
```
1. nargo compile      → circuits/target/*.json
2. sunspot compile    → circuits/target/*.ccs
3. sunspot setup      → target/*.pk, target/*.vk
4. sunspot deploy     → *_verifier.so
5. Uploads all artifacts for download
6. (Optional) Deploys verifiers to Solana devnet
```

### 5.3 How to Trigger the Workflow

**Option 1: Automatic (on push to main)**
```bash
# If you changed circuit sources, push to main
git add circuits/
git commit -m "Update circuits"
git push origin main
```
The workflow auto-triggers when `circuits/**` files change.

**Option 2: Manual trigger**
1. Go to GitHub → **Actions** → **"Build Sunspot Verifiers"**
2. Click **"Run workflow"**
3. (Optional) Check **"Deploy to devnet"** if you need new verifier program IDs

### 5.4 After the Workflow Completes

1. **Download artifacts** from the workflow run:
   - Go to the completed workflow run
   - Download the `solana-verifiers` artifact (zip file)

2. **Artifact contents:**
   ```
   solana-verifiers/
   ├── deal_proof_verifier.so           # Compiled Solana program
   ├── deal_proof_verifier-keypair.json # For deployment
   ├── reveal_proof_verifier.so
   ├── reveal_proof_verifier-keypair.json
   ├── shuffle_proof_verifier.so
   ├── shuffle_proof_verifier-keypair.json
   └── target/
       ├── deal_proof.ccs               # Constraint system (for local sunspot prove)
       ├── deal_proof.pk                # Proving key
       ├── deal_proof.vk                # Verifying key
       ├── reveal_proof.ccs
       ├── reveal_proof.pk
       ├── reveal_proof.vk
       ├── shuffle_proof.ccs
       ├── shuffle_proof.pk
       └── shuffle_proof.vk
   ```

3. **Copy files to your project:**
   ```bash
   # Extract the downloaded zip (adjust path as needed)
   unzip solana-verifiers.zip -d ~/Downloads/

   # IMPORTANT: Copy ALL Sunspot artifacts
   # .ccs files go to circuits/target/ (for /api/prove)
   cp ~/Downloads/solana-verifiers/target/*.ccs circuits/target/

   # .pk and .vk files go to solana-verifiers/target/
   cp ~/Downloads/solana-verifiers/target/*.pk solana-verifiers/target/
   cp ~/Downloads/solana-verifiers/target/*.vk solana-verifiers/target/

   # (Optional) Copy verifier programs for manual deployment
   cp ~/Downloads/solana-verifiers/*_verifier.so solana-verifiers/
   cp ~/Downloads/solana-verifiers/*_verifier-keypair.json solana-verifiers/
   ```

   **Quick one-liner (from project root):**
   ```bash
   cp solana-verifiers/target/*.ccs circuits/target/
   ```

4. **Sync browser circuits locally:**
   ```bash
   npm run sync-circuits
   ```

> ⚠️ **Critical:** The `.ccs` files MUST be copied to `circuits/target/` (not `solana-verifiers/target/`). The `/api/prove` endpoint uses `circuits/target/*.ccs` for local proof generation.

### 5.5 What You CAN Do Locally

These steps work locally without Sunspot:

```bash
# === Compile Noir Circuits (works locally) ===
cd circuits
(cd shuffle_proof && nargo compile)
(cd deal_proof && nargo compile)
(cd reveal_proof && nargo compile)
(cd hash_14_helper && nargo compile)
(cd hash_2_helper && nargo compile)

# === Sync to Browser (works locally) ===
cd /Users/marcus/Projects/solanaprivacyhack
npm run sync-circuits

# === Run Circuit Tests (works locally) ===
(cd circuits/shuffle_proof && nargo test)
(cd circuits/deal_proof && nargo test)
(cd circuits/reveal_proof && nargo test)
```

### 5.6 What Requires GitHub Workflow

These steps MUST use the GitHub workflow:

| Step | Command | Output Files | Why |
|------|---------|--------------|-----|
| Compile constraints | `sunspot compile` | `.ccs` (not in artifact) | Sunspot version mismatch |
| Generate keys | `sunspot setup` | `.pk`, `.vk` | Sunspot version mismatch |
| Build verifier | `sunspot deploy` | `*_verifier.so` | Requires cargo-build-sbf |

**Files you get from the workflow artifact:**
- `*.ccs` - Constraint systems (copy to `circuits/target/`) - **required for local proof generation**
- `*.pk` - Proving keys (copy to `solana-verifiers/target/`)
- `*.vk` - Verifying keys (copy to `solana-verifiers/target/`)
- `*_verifier.so` - Compiled Solana programs (for manual deployment)
- `*_verifier-keypair.json` - Program keypairs (for deployment)

## 6. Verification Checklist

### 6.1 After Downloading Workflow Artifacts

```bash
# 1. Copy .ccs files to circuits/target/
cp solana-verifiers/target/*.ccs circuits/target/

# 2. Verify all artifact sizes are for 13-card deck
echo "=== .ccs files (should be <300KB) ===" && ls -lh circuits/target/*.ccs
echo "=== .pk files (should be <3MB) ===" && ls -lh solana-verifiers/target/*.pk

# 3. Verify circuit sources match
grep -n "shuffled_deck:" circuits/*/src/main.nr
# Expected: [u8; 13] for 13-card deck

# 4. Sync browser circuits
npm run sync-circuits

# 5. Verify public circuits synced
diff -q circuits/target/shuffle_proof.json public/shuffle_proof.json && echo "✓ synced"
```

### 6.2 Quick Verification Command

```bash
# One command to verify everything is consistent
echo "Sources:" && grep "shuffled_deck:" circuits/*/src/main.nr && \
echo "" && echo ".ccs sizes:" && ls -lh circuits/target/*.ccs && \
echo "" && echo ".pk sizes:" && ls -lh solana-verifiers/target/*.pk
```

### 6.3 Before Deploying to Production

```bash
# 1. Test full proof generation locally
npm run dev
# Visit http://localhost:3000/zk-game-test

# 2. Verify no random fallbacks
grep -n "Math.random" hooks/useGameProgram.js
# Should return nothing

# 3. Test on-chain verification (devnet)
anchor test

# 4. Check program logs for CU usage
solana logs 8Da8a3Q9GLYuxYLXPtxKiAedZZbx5DUQCuG8TPY1dLnx
```

## 8. For AI Agents: Decision Tree

When encountering ZK-related errors:

```
1. Is the error "invalid witness size"?
   └── YES → Artifacts out of sync
       └── Check: ls -lh circuits/target/*.ccs
           └── If sizes don't match deck size → TRIGGER GITHUB WORKFLOW
               (Sunspot cannot run locally - see Section 5)

2. Is the error "Circuit X not found"?
   └── YES → Missing public/*.json
       └── Run: npm run sync-circuits (works locally)

3. Is the error "Proof verification failed on-chain"?
   └── YES → Verifier mismatch
       └── TRIGGER GITHUB WORKFLOW with "Deploy to devnet" checked

4. Is the error about constraint counts?
   └── YES → Version mismatch
       └── Check nargo --version and Poseidon version in Nargo.toml

5. Need to rebuild Sunspot artifacts (.ccs, .pk, .vk)?
   └── YES → TRIGGER GITHUB WORKFLOW
       └── Download artifacts after completion
       └── Copy to solana-verifiers/target/
```

### Critical Reminder for AI Agents

**DO NOT attempt to run `sunspot compile`, `sunspot setup`, or `sunspot deploy` locally.**

These commands will fail due to toolchain version mismatches. Always direct the user to:
1. Push circuit changes to `main` branch, OR
2. Manually trigger the GitHub workflow at Actions → "Build Sunspot Verifiers"
